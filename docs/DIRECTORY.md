# Адресная книга: Active Directory и LDAP

Приложение `directory` ищет контакты в корпоративном каталоге (Active Directory, OpenLDAP, 389 DS, FreeIPA, адресная книга почтового сервера). **Поиск выполняется на сервере каталога** при каждом запросе пользователя — контакты не копируются в базу календаря, поэтому всегда актуальны.

- **Настраивает только администратор** (роль «Администратор» или суперпользователь): в админке и через API настройки. Остальным ролям раздел админки и API настройки недоступны (`403`).
- **Контакты доступны всем вошедшим пользователям, независимо от роли**, даже без единой роли: окно «Контакты», подсказки в поле «Гости» и `GET /api/contacts/`.
- Пароль учётной записи для подключения хранится зашифрованным и нигде не показывается.
- Если сервер каталога недоступен, поиск контактов не работает (пользователь видит «Каталог временно недоступен», администратор — причину).

## Подключение

Админка → **«Адресная книга (AD / LDAP)» → «Каталоги (AD / LDAP)» → «Добавить»** (или кнопка «Контакты» → «Настроить каталоги»).

### Основное

| Поле | Пример | Пояснение |
|---|---|---|
| Название | `YG` | как каталог будет подписан у пользователей |
| Тип каталога | LDAP | «Active Directory» — стандартные атрибуты и фильтр AD; «LDAP» — для остальных серверов |
| Имя сервера | `email.yanao.ru` | несколько серверов (резерв) — через запятую; можно `ldaps://имя:порт` |
| Корневой элемент (Base DN) | `cn=yg.loc` | откуда искать; для AD обычно `DC=домен,DC=loc` |
| Порт | `636` | 636 — LDAPS (шифрование включается само), 389 — LDAP/StartTLS, 3269 — глобальный каталог AD по SSL |
| Имя пользователя (Bind DN) | `user@yanao.ru` | также `DOMAIN\user` или полный DN; пусто — анонимный вход |
| Пароль | | хранится зашифрованным; пустое поле при сохранении не меняет пароль |

Кнопки внизу формы:

- **«Сохранить и проверить подключение»** — вход и поиск нескольких записей. Показывает примеры найденных контактов и **список атрибутов, которые реально пришли с сервера**: по нему удобно поправить сопоставление полей.
- **«Сохранить и проверить поиск»** — выполняет на сервере поиск по полю «Проверочный запрос» (например, `Петров`) так же, как его выполнит адресная книга, и показывает найденных.

### Дополнительно

| Поле | По умолчанию |
|---|---|
| Шифрование | «Автоматически»: для порта 636 и `ldaps://` — LDAPS, иначе без шифрования. Можно выбрать StartTLS |
| Проверять сертификат сервера | включено. Для сертификата внутреннего центра сертификации укажите путь к его корневому сертификату (`.pem`) или, только для проверки, отключите проверку |
| Фильтр поиска | AD: люди без отключённых учётных записей и объекты-контакты. LDAP: `person`, `inetOrgPerson`, `organizationalPerson`, `user`, `contact` |
| Сопоставление атрибутов | только отличия от стандартного, JSON |
| Результатов на запрос | 50 — не больше стольких записей запрашивается у сервера за один поиск |

Стандартное сопоставление (поле контакта → атрибут каталога):

| Поле | Active Directory | LDAP |
|---|---|---|
| `id` (постоянный идентификатор) | `objectGUID` | `entryUUID` (если его нет — DN) |
| `display_name` | `displayName` | `displayName` |
| `last_name` / `first_name` | `sn` / `givenName` | `sn` / `givenName` |
| `middle_name` | `middleName` | — |
| `email` | `mail` | `mail` |
| `phone` / `mobile` | `telephoneNumber` / `mobile` | `telephoneNumber` / `mobile` |
| `title` | `title` | `title` |
| `department` | `department` | `ou` |
| `company` | `company` | `o` |
| `office` | `physicalDeliveryOfficeName` | `physicalDeliveryOfficeName` |

Пример переопределения: `{"department": "departmentNumber", "id": "nsUniqueId"}`. Если имени нет ни в одном атрибуте, оно собирается из фамилии и имени, затем берётся `cn`. Записи без имени и без e-mail (служебные объекты) пропускаются.

### Про пример `email.yanao.ru`, `cn=yg.loc`, `user@yanao.ru`

Base DN вида `cn=yg.loc` не похож на Active Directory (там `DC=yg,DC=loc`). Скорее всего, это LDAP-адресная книга почтового сервера, поэтому начните с типа **LDAP**:

1. Заполните «Основное» как в таблице выше, сохраните кнопкой «Сохранить и проверить подключение».
2. Если записей не нашлось — попробуйте фильтр `(mail=*)`.
3. Посмотрите список пришедших атрибутов и при необходимости поправьте сопоставление (например, подразделение может быть в `departmentNumber`, а идентификатор — в `uid`).
4. Введите «Проверочный запрос» и нажмите «Сохранить и проверить поиск».

То же из командной строки: `python manage.py directory_check` покажет найденные записи и атрибуты, `python manage.py directory_check --search Петров` — результат поиска.

## Как работает поиск

1. Пользователь вводит запрос (от 2 символов). После паузы в наборе (0,3 с) запрос уходит на сервер календаря, а с него — **на сервер каталога**, во все включённые каталоги параллельно.
2. Из запроса строится LDAP-фильтр: каждое слово должно найтись в каком-нибудь поле —
   по началу в фамилии, имени, отчестве, e-mail; по вхождению в полном имени (`displayName`, `cn`), должности, подразделении, кабинете.
   Для Active Directory добавляется ANR (поиск по имени, фамилии, логину). Пример для «Петров ив»:
   ```
   (&<фильтр каталога>(|(sn=Петров*)(givenName=Петров*)(mail=Петров*)(displayName=*Петров*)(cn=*Петров*)…)(|(sn=ив*)…))
   ```
   Похожий на телефон запрос ищется по цифрам в любом формате: `4-12-34` → `(telephoneNumber=*4*1*2*3*4*)`.
   Буквы «е» и «ё» ищутся в обоих написаниях. Спецсимволы запроса экранируются (RFC 4515) — подменить фильтр нельзя.
3. Найденные записи ранжируются: точное совпадение фамилии/имени/ФИО/e-mail первым, затем по началу, по словам, по вхождению. Один и тот же e-mail из двух каталогов показывается один раз.
4. Контакт связывается с пользователем календаря по совпадению e-mail: такой контакт помечается «в календаре» и при приглашении добавляется в событие **участником**, а не гостем.

Нагрузка на сервер каталога:

- соединение с каталогом открывается один раз и переиспользуется (простаивающее дольше 5 минут — переоткрывается; разорванное сервером — переоткрывается автоматически);
- одинаковый запрос в течение `DIRECTORY_CACHE_SECONDS` (60 с) повторно на сервер не отправляется;
- не больше «Результатов на запрос» (50) записей и 5 секунд на один поиск;
- запросы короче 2 символов на сервер не отправляются.

Таймаут подключения — `DIRECTORY_TIMEOUT` (15 с).

Проверка из командной строки:

```bash
python manage.py directory_check                     # подключение: примеры записей и атрибуты
python manage.py directory_check --search Петров     # поиск, как в адресной книге
python manage.py directory_check --diagnose          # DNS и доступность LDAP-портов, без входа
python manage.py directory_check --id 1              # только один каталог
```

## Для пользователей

- Кнопка **«Контакты»** в шапке — поиск на сервере каталога по ФИО (в любом порядке), e-mail, телефону (в любом формате), должности, подразделению; от 2 символов. ↑/↓ — выбор, Enter — карточка контакта.
- В карточке: телефоны и e-mail ссылками, «Пригласить на событие», «Написать письмо», «Скопировать e-mail».
- В форме события в поле **«Гости»** начните вводить фамилию — появятся подсказки из адресной книги.
- Участник, выбранный из адресной книги (в поле «Гости» или кнопкой «Пригласить на событие» в карточке), **автоматически получает событие в свой календарь**, а при изменении или удалении события — обновление или отмену. Под полем «Гости» показывается, сколько таких участников. Письма уходят через почтовый сервер из админки («Почтовый сервер (отправка приглашений)») или через Exchange владельца. Подробнее — в [INTEGRATIONS.md](INTEGRATIONS.md#участники-из-адресной-книги).

## Частые ошибки

| Сообщение | Что сделать |
|---|---|
| Сервер каталога недоступен: … timed out | сервер календаря не может открыть соединение с каталогом. Проверка подключения сама покажет адрес в DNS и какие порты (636, 389, 3269, 3268) отвечают, см. ниже |
| Неверное имя пользователя (Bind DN) или пароль | для AD используйте `user@домен` или `DOMAIN\user` |
| Сервер требует шифрования | порт 636 (LDAPS) или шифрование StartTLS |
| Ошибка проверки сертификата | укажите файл корневого сертификата (CA) или временно отключите проверку |
| Корневой элемент (Base DN) не найден | проверьте написание Base DN |
| Поиск ничего не находит, хотя подключение успешно | проверьте поиском в админке; посмотрите атрибуты в «Проверить подключение» и поправьте сопоставление (например, фамилия может быть только в `cn`) |
| У учётной записи нет прав на поиск в каталоге | выдайте учётной записи из «Имя пользователя (Bind DN)» право чтения в Base DN |
| Не установлена библиотека ldap3 | `pip install -r requirements.txt` |

### Сервер каталога недоступен (timed out)

Ошибка сетевая: до логина и пароля дело не дошло. Проверка подключения (кнопка в админке, `directory_check` или `directory_check --diagnose`) выводит, например:

```
email.yanao.ru → 195.x.x.x
порт 636 — LDAPS (указан в настройках): нет ответа — вероятно, закрыт файрволом или сервер недоступен из этой сети
порт 389 — LDAP / StartTLS: открыт
Совет: укажите порт 389 и шифрование «StartTLS» …
```

- **Открыт другой порт** — укажите его (для 389 — шифрование StartTLS).
- **Ни один порт не отвечает** — каталог, скорее всего, доступен только из внутренней сети или через VPN, либо LDAP-сервер имеет другой адрес (например, внутренний `dc1.yg.loc` вместо внешнего `email.yanao.ru`). Попросите администратора сети открыть доступ с сервера календаря или сообщить внутренний адрес.
- **Имя не найдено в DNS** — проверьте написание и DNS-серверы машины, где работает календарь.

Проверка выполняется с той машины, где запущен календарь: с рабочего компьютера и с сервера результат может различаться. Те же проверки вручную:

```bash
getent hosts email.yanao.ru                       # DNS (Windows: nslookup email.yanao.ru)
nc -vz -w 5 email.yanao.ru 636                    # порт (Windows PowerShell: Test-NetConnection email.yanao.ru -Port 636)
openssl s_client -connect email.yanao.ru:636 </dev/null   # TLS-рукопожатие и сертификат
```

## Устройство

```
directory/
  ldap_client.py   подключение через ldap3, пул соединений, LDAP-фильтр из запроса, ранжирование,
                   разбор записей, сетевая диагностика (не зависит от Django)
  models.py        DirectorySource (каталог)
  search.py        поиск во всех включённых каталогах, кэш, связь с пользователями календаря
  views.py, urls.py  API адресной книги (всем) и настройки (администратору)
  admin.py         настройка каталогов, кнопки проверки подключения и поиска
  management/commands/directory_check.py
```

Тесты: `python manage.py test directory`. Построение фильтра, разбор записей и ранжирование проверяются и без Django: `python -m unittest directory.tests_client`.

> Миграция `directory/0002` удаляет таблицу контактов, которая была в первой версии (с загрузкой в базу): она больше не нужна. Команды `sync_directory` больше нет (вместо неё — `directory_check`); если она стоит в cron — уберите её.

# Внешние календари

Приложение `integrations` синхронизирует **собственный календарь пользователя** с внешними календарями в обе стороны, а также рассылает приглашения на события письмом с файлом `.ics`.

| Сервис | Как подключается | Что нужно |
|---|---|---|
| Google Календарь | Google Calendar API, вход через OAuth | один раз настроить OAuth-клиент (см. ниже) |
| **Microsoft Exchange (Outlook)** | EWS, по умолчанию `https://email.yanao.ru/EWS/Exchange.asmx` | доменный логин (`DOMAIN\пользователь` или адрес почты) и пароль |
| Яндекс Календарь | CalDAV, `https://caldav.yandex.ru` | логин и **пароль приложения** «Календарь» из Яндекс ID |
| Календарь Mail.ru | CalDAV, `https://calendar.mail.ru` | полный адрес ящика и **пароль для внешнего приложения** |
| Рамблер Календарь | CalDAV, по умолчанию `https://calendar.rambler.ru` | логин и пароль; адрес сервера проверьте в настройках Рамблер Календаря |
| Другой CalDAV | CalDAV, свой адрес | Nextcloud, iCloud, Zimbra и т. п. |
| Любая почта | приглашение письмом с `.ics` | настроить отправку почты (см. ниже) |

> Адрес CalDAV-сервера Рамблера не удалось подтвердить по открытой документации, поэтому он редактируется при подключении. Если подключиться не получается, приглашайте людей с адресами на Рамблере через поле «Гости» в событии — им придёт письмо с приглашением.

## Как пользоваться

1. Шестерёнка в шапке → **«Интеграции»** → **«Подключить календарь»**.
2. Выберите сервис.
   - Microsoft Exchange: доменный логин и пароль → **«Найти календари»** (основной календарь и его подпапки).
   - Яндекс / Mail.ru / Рамблер / CalDAV: введите логин и пароль приложения → **«Найти календари»**.
   - Google: **«Войти через Google»** → разрешите доступ → календари Google покажутся сами.
3. Выберите календарь, направление синхронизации и цвет его событий у нас → **«Подключить»**. Сразу выполняется первая синхронизация.

Для каждого подключённого календаря можно сменить направление и цвет, временно выключить синхронизацию, запустить её вручную, задать новый пароль (если старый перестал работать) или отключить календарь — с удалением импортированных событий или без.

### Как работает синхронизация

- Синхронизируются события в окне **30 дней назад — 365 дней вперёд** (`INTEGRATIONS_SYNC_PAST_DAYS`, `INTEGRATIONS_SYNC_FUTURE_DAYS`).
- Новое событие с одной стороны создаётся на другой; изменение и удаление тоже переносятся.
- Если событие изменили с обеих сторон между синхронизациями, побеждает **более позднее** изменение.
- Направления: «В обе стороны», «Только оттуда к нам», «Только от нас туда». Календарь, доступный во внешнем сервисе только для чтения, подключается только на импорт.
- **Повторяющиеся события** из внешних календарей импортируются как отдельные экземпляры «только для чтения»: если изменить такой экземпляр у нас, при следующей синхронизации вернётся версия из внешнего календаря.
- Во внешний календарь уходят события, созданные в нашем календаре. События, импортированные из одного внешнего календаря, в другие внешние календари **не** копируются.
- Синхронизируются название, описание, место, ссылка, время и «весь день».
- **Из Microsoft Exchange (Outlook) к нам** приходят также **участники и вложения** событий, созданных в Outlook: сотрудники, у которых есть учётная запись в календаре, — в «Приглашённые» (событие появляется и у них), остальные адреса — в «Гости»; файлы — во вложения события (до 20 МБ каждый, `INTEGRATIONS_MAX_ATTACHMENT_SIZE`). Когда участников или файлы меняют в Outlook, изменения приходят при следующей синхронизации; повторно файлы не скачиваются. Приглашения таким участникам мы не рассылаем — это уже сделал Outlook. Если коллега, приглашённый на такую встречу, сам подключил Exchange, его копия встречи не импортируется второй раз.
- **От нас в Exchange** уходят и **файлы**: прикреплённый к событию файл сразу добавляется вложением к событию в Exchange, удалённый — удаляется там. Если Exchange был недоступен, файлы досылает плановая синхронизация. Участникам собрания (из адресной книги) при этом уходит обновление с файлами. Участники в Exchange передаются только выбранные из адресной книги (см. «Участники из адресной книги»).
- События, записанные в Exchange прошлой версией календаря (ссылка была скрытой), при ближайшей синхронизации перезаписываются: ссылка появляется в тексте события. Участникам при этом ничего не рассылается.
- Защита от сбоев: если сервер вдруг вернул пустой календарь, а у нас есть связанные с ним события, удаления не выполняются.

### Мгновенная отправка при добавлении и изменении события

Как только событие **создано, изменено, перенесено (в том числе перетаскиванием) или удалено** — через календарь, API или админку, — оно сразу отправляется во все подключённые календари владельца, где разрешено направление «от нас туда» (например, в календарь Exchange, который видно в Outlook и OWA).

- Отправка идёт после сохранения в фоне: пользователь не ждёт ответа почтового сервера.
- Если меняется только цвет (он во внешние календари не передаётся), запрос не отправляется.
- Если сервер недоступен или пароль устарел, событие всё равно сохраняется у нас, а в карточке подключения появляется ошибка «Не удалось сразу отправить…». Плановая синхронизация досылает такие события.
- Если событие одновременно изменили и в Outlook, отправка откладывается до плановой синхронизации — она выберет более позднюю версию.
- Изменения, сделанные в Outlook, к нам попадают при плановой синхронизации (см. ниже) или по кнопке «Синхронизировать».

Настройки (`main/settings.py`): `INTEGRATIONS_PUSH_ON_SAVE` — включить/выключить мгновенную отправку (по умолчанию включена), `INTEGRATIONS_PUSH_ASYNC` — отправлять в фоновом потоке (по умолчанию да; `False` — синхронно, удобно для отладки).

### Участники из адресной книги

Если участника добавили в событие **из адресной книги Active Directory / LDAP** (подсказка в поле «Гости» или «Пригласить на событие» в карточке контакта), событие автоматически появляется в **его** календаре и дальше обновляется:

| Что сделали | Что получает участник |
|---|---|
| добавили участника | приглашение — событие появляется в его календаре |
| изменили название, время, место, описание или ссылку | обновление — событие меняется у него в календаре |
| сменили только цвет | ничего |
| убрали участника из события | отмену — событие исчезает из его календаря |
| удалили событие | отмену |

Как доставляется:

- **У владельца события подключён Microsoft Exchange** — событие в Exchange становится собранием с этими участниками, приглашения и обновления рассылает сам Exchange. Встреча появляется в календарях участников (Outlook, OWA, телефон) так же, как если бы её создали в Outlook; участники могут принять или отклонить её.
- **Exchange не подключён** — каждому участнику уходит письмо с приглашением (`.ics`, `METHOD:REQUEST`), при изменении — обновление с тем же UID, при удалении — отмена (`METHOD:CANCEL`). Outlook/Exchange, Яндекс, Mail.ru, Gmail ставят такое событие в календарь сами (Exchange — «под вопросом», до ответа участника). Нужна настроенная отправка почты (см. ниже).
- Участник, у которого есть учётная запись в нашем календаре (совпадает e-mail), кроме того видит событие у нас — с правом чтения. Если он сам подключил свой Exchange, встреча оттуда не импортируется повторно (узнаётся по UID).
- Адрес, вписанный в «Гости» вручную, тоже считается участником из адресной книги, если такой e-mail найден в AD/LDAP (проверяется при сохранении). Остальные гости автоматически ничего не получают — для них галочка «Отправить приглашения по e-mail»; участникам, уже получившим событие автоматически, она повторно не пишет.
- Если у владельца подключён Exchange, но он недоступен, новым участникам приглашение сразу уходит письмом, а в собрание Exchange они добавятся при следующей синхронизации (без повторного приглашения).
- После сохранения события внизу экрана видно, кому ушло приглашение, обновление или отмена, — или почему не ушло.
- Если Exchange или почтовый сервер были недоступны, приглашения досылает плановая синхронизация (`sync_calendars`). Изменения собрания, сделанные организатором в Outlook, Exchange рассылает сам — повторно мы их не отправляем.
- Что и кому отправлено, видно в админке: «Внешние календари» → «Доставка участникам».

### Автоматическая синхронизация

Запускайте команду по расписанию, например каждые 10 минут:

```bash
python manage.py sync_calendars                 # все включённые календари
python manage.py sync_calendars --user ivan     # календари одного пользователя
python manage.py sync_calendars --id 3 --id 5   # выбранные
```

Пример для cron:

```
*/10 * * * * cd /путь/к/проекту/main && /путь/к/.venv/bin/python manage.py sync_calendars >> /var/log/calendar-sync.log 2>&1
```

Кроме того, синхронизацию можно запустить кнопками в окне «Интеграции» и действием «Синхронизировать сейчас» в админке.

## Настройка

Все настройки — переменные окружения (см. конец `main/settings.py`).

### Google Календарь

1. [Google Cloud Console](https://console.cloud.google.com/) → создайте проект.
2. «APIs & Services» → «Library» → включите **Google Calendar API**.
3. «OAuth consent screen» — заполните название приложения; пока приложение не опубликовано, добавьте пользователей в «Test users».
4. «Credentials» → «Create credentials» → «OAuth client ID» → тип **Web application**.
   В «Authorized redirect URIs» добавьте `<адрес сайта>/integrations/google/callback/`,
   например `http://127.0.0.1:8000/integrations/google/callback/` для разработки.
5. Задайте переменные окружения и перезапустите сервер:

```bash
export GOOGLE_OAUTH_CLIENT_ID="....apps.googleusercontent.com"
export GOOGLE_OAUTH_CLIENT_SECRET="..."
```

Без этих переменных пункт «Google Календарь» показывается, но кнопка входа недоступна.

### Microsoft Exchange

Подключение идёт через Exchange Web Services (EWS) — так же работает Outlook на Mac и мобильные клиенты.

- Адрес по умолчанию: `INTEGRATIONS_EXCHANGE_URL` (`https://email.yanao.ru/EWS/Exchange.asmx`). При подключении его можно изменить; достаточно ввести имя сервера — путь `/EWS/Exchange.asmx` добавится сам.
- Логин: `YG\ivanov`, `ivanov@yanao.ru` или `ivanov@yg.loc` — как для входа в OWA.
- Способ входа (NTLM или Basic) определяется по ответу сервера. Для NTLM нужен пакет `requests_ntlm` (есть в `requirements.txt`).
- Поддерживается Exchange 2010 SP2 и новее.
- Ссылка события хранится в Exchange **в открытом виде** — в тексте события после описания, через пустую строку:

  ```
  Повестка: бюджет на 2027 год

  https://bbb.yanao.ru/b/abc-def
  ```

  В Outlook и OWA она видна и кликабельна. При синхронизации последний абзац снова становится полем «Ссылка», а остальной текст — «Описанием»; ссылку можно поправить прямо в Outlook (удалить ссылку — в календаре, очистив поле «Ссылка»). Описание, которое само заканчивается адресом, не путается со ссылкой: ссылкой считается последний абзац только у событий, где ссылку задали в календаре (это отмечается служебным свойством события).
- В Exchange участниками собрания становятся только участники, выбранные из адресной книги (см. «Участники из адресной книги»); остальные события создаются без рассылки приглашений. Гостям, вписанным вручную, приглашение отправляет кнопка «Пригласить».
- Повторяющиеся встречи из Outlook импортируются отдельными экземплярами только для чтения.

### Шифрование паролей и токенов

Пароли приложений и токены Google хранятся в базе зашифрованными (Fernet). Ключ — `INTEGRATIONS_ENCRYPTION_KEY`; если он не задан, ключ выводится из `SECRET_KEY`. Для боевого сервера задайте отдельный ключ:

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
export INTEGRATIONS_ENCRYPTION_KEY="<результат>"
```

При смене ключа (или `SECRET_KEY`, если ключ не задан) сохранённые пароли перестанут расшифровываться — календари нужно будет подключить заново или задать им новый пароль.

### Почта для приглашений

**Без настроенной почты письма никуда не уходят** — только выводятся в консоль сервера. Это частая причина того, что «уведомление не приходит»: после сохранения события календарь теперь прямо пишет «Почтовый сервер не настроен — письма не отправляются».

Настройка (администратор): **админка → «Внешние календари» → «Почтовый сервер (отправка приглашений)» → «Добавить»**.

| Поле | Пример для Exchange `email.yanao.ru` |
|---|---|
| Сервер SMTP | `email.yanao.ru` |
| Порт / Шифрование | `587` / STARTTLS (или `465` / SSL/TLS; `25` / без шифрования — если сервер принимает письма от сервера календаря без входа) |
| Логин и пароль | служебная учётная запись с почтовым ящиком, например `calendar@yanao.ru` |
| Адрес отправителя | тот же `calendar@yanao.ru` — Exchange не даёт отправлять от чужого адреса без права «Отправить как» |
| Проверять сертификат | снимите, если у сервера внутренний (самоподписанный) сертификат |

**От кого приходят приглашения.** По умолчанию — от «Адреса отправителя» из этих настроек; ответы приходят владельцу события (поле «Ответить»). Почтовый сервер `email.yanao.ru` не разрешает ставить отправителем адрес, не совпадающий с учётной записью входа: письмо принимается, а затем возвращается с ошибкой «Not allowed address». Чтобы приглашения уходили **от адреса пользователя, создавшего событие**, администратор почты должен разрешить учётной записи календаря отправлять от адресов сотрудников («Отправить как»), после чего в `.env` включается `INTEGRATIONS_MAIL_FROM_USER=1`. Тогда отправителем становится «Имя Фамилия <адрес>» автора события (неизвестен — владельца календаря), организатором в приглашении остаётся владелец. Если у владельца подключён Exchange, приглашения рассылает сам Exchange от учётной записи владельца.

**Файлы события.** Файлы, прикреплённые к событию, вкладываются в письмо-приглашение рядом с `invite.ics` — почтовый сервер получателя переносит их в событие его календаря. При создании события с файлами приглашение уходит после загрузки файлов, одним письмом; если файл добавили или удалили позже, участникам уходит обновление. В письмо попадает не больше `INTEGRATIONS_MAIL_MAX_ATTACHMENTS_MB` (20 МБ) файлов в сумме — остальные перечисляются в тексте письма и доступны в календаре. В письма об отмене файлы не вкладываются.

Кнопка **«Сохранить и отправить тестовое письмо»** сразу проверяет настройки и показывает понятную причину ошибки (неверный пароль, отправитель не разрешён, порт закрыт, сертификат и т. п.). Последняя ошибка отправки видна в списке почтовых серверов. В письмах-приглашениях «Ответить» адресовано организатору события.

Можно и по-старому — переменными окружения (используются, если в админке почтовый сервер не задан):

```bash
export EMAIL_HOST=email.yanao.ru
export EMAIL_PORT=587
export EMAIL_USE_SSL=0
export EMAIL_USE_TLS=1
export EMAIL_HOST_USER=calendar@yanao.ru
export EMAIL_HOST_PASSWORD="пароль"
export DEFAULT_FROM_EMAIL=calendar@yanao.ru
```

### Приглашения

В форме события — поле **«Гости (e-mail)»** (адреса через запятую) и галочка **«Отправить приглашения по e-mail»**. При сохранении каждому приглашённому сотруднику (с e-mail) и гостю уходит отдельное письмо с файлом `invite.ics`; почтовые программы и веб-почта показывают кнопку добавления в календарь. При удалении события с этой галочкой участникам уходит отмена.

## Устройство

```
integrations/
  ics.py              разбор и генерация iCalendar, развёртка RRULE (без внешних библиотек)
  providers/caldav.py CalDAV: поиск календарей, REPORT, PUT/DELETE с ETag
  providers/google.py Google Calendar API v3 и OAuth
  crypto.py           шифрование паролей и токенов
  models.py           ExternalCalendar (подключение), SyncedEvent (связь событий)
  sync.py             движок двусторонней синхронизации
  invitations.py      письма-приглашения с .ics
  views.py, urls.py   API и вход через Google
  management/commands/sync_calendars.py
  testing.py          тестовый CalDAV-сервер для автотестов
```

Тесты: `python manage.py test integrations`. Тесты `tests_ics` и `tests_providers` не требуют Django: `python -m unittest integrations.tests_ics integrations.tests_providers`.
